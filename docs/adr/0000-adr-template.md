#### This template is inspired by the [Michael Nygard's format](https://github.com/joelparkerhenderson/architecture-decision-record/tree/main/locales/en/templates/decision-record-template-by-michael-nygard)


# [Short noun phrase describing the decision]

**Date:** YYYY-MM-DD
**Status:** [Proposed | Accepted | Rejected | Superseded by ADR-XXXX]

## Context
*What is the technical or business problem we are trying to solve?*
* Describe the forces at play (e.g., performance constraints, timeline, developer experience).
* If there are alternative options being considered, list them here.

## Decision
*What exactly are we doing?*
* Write this in active voice: "We will use..." or "We are building..."
* Keep it clear and unambiguous.

## Consequences
*What happens now that we've made this choice?*
* **Positive:** (e.g., "Developer onboarding is faster.")
* **Negative:** (e.g., "Our Docker image size increases by 50MB.")
* **Neutral/Risks:** (e.g., "We will need to train contributors on how to use this new tool.")
